## DeskAgent

Desktop-агент с LangGraph и сменными локальными и API LLM-провайдерами.

Архитектура политик, подтверждений, audit log и аварийной остановки описана в [SECURITY.md](SECURITY.md).

```bash
# Локальная модель через Ollama
python scripts/run_agent.py --provider ollama --model qwen3:4b "Покажи заряд батареи"

# Локальная модель через MLX
python scripts/run_llm.py --provider mlx --model ./models/model "Привет"
```

## GigaChat API

Установите зависимости и положите параметры доступа в `.env` в корне проекта:

```bash
pip install -r requirements.txt
```

```dotenv
GIGACHAT_CREDENTIALS=<authorization-key>
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=<model-name>
```

Файл `.env` исключён из Git. Запуск через API не поднимает локальную модель:

```bash
python scripts/run_agent.py --provider gigachat "Покажи заряд батареи"
python scripts/run_llm.py --provider gigachat --stream "Привет"
```

Для TLS используется включённый в проект корневой сертификат НУЦ Минцифры из
`models/gigachat/russian_trusted_root_ca_pem.crt`. При необходимости его можно
переопределить через `GIGACHAT_CA_BUNDLE_FILE`. Отключать проверку TLS не следует.

Параметры локальных провайдеров можно хранить в `config.yaml` или переменных
окружения `DESKAGENT_*`. Аргументы командной строки имеют приоритет над `.env` и
конфигурацией.
Полный список аргументов доступен через `--help`.

## Сессии, планы и автопилот

Пакет `deskagent.autopilot` выполняет сохраняемые многошаговые планы поверх
существующего каталога действий. Он поддерживает DAG-зависимости и параллельные
ветки, передачу результатов между шагами, декларативную проверку, безопасные
повторы, строгие подтверждения, перепланирование, компенсации, отмену и
автоматическое восстановление после перезапуска.

```python
from deskagent.autopilot import AutopilotEngine, Plan, SessionStore, Step

store = SessionStore("data/sessions.sqlite")
engine = AutopilotEngine(action_catalog, store)
session = engine.create_session(
    "Подготовить рабочее окружение",
    Plan([
        Step(
            id="open_ide",
            title="Открыть PyCharm",
            action="launch_application",
            arguments={"application": "PyCharm"},
            idempotent=True,
        ),
        Step(
            id="set_volume",
            title="Установить громкость",
            action="set_volume",
            arguments={"volume": 25},
            depends_on=("open_ide",),
            idempotent=True,
        ),
    ]),
)
result = engine.start(session.id)
```

Сохранённые сценарии описываются декларативным YAML без выполнения произвольного
Python или shell-кода. Пример находится в `examples/prepare_for_work.yaml`.

Для длительно работающего приложения используется `AutopilotWorker`: он честно
обходит активные сессии, удерживает lease только на время одного тика и запускает
готовые повторы по сохранённому `retry_at`. Независимые шаги выполняются параллельно,
если их `resources` не пересекаются.

Управление workflow из терминала:

```bash
python scripts/run_workflow.py save examples/prepare_for_work.yaml
python scripts/run_workflow.py run prepare_for_work --inputs '{"focus_volume": 25}'
python scripts/run_workflow.py list
python scripts/run_workflow.py status <session-id>
```

Секретные входы workflow содержат только имя секрета. Значение разрешается во
время выполнения из переменной `DESKAGENT_SECRET_<NAME>` и не записывается в план,
журнал событий или историю запусков.

## Accessibility на macOS

Модуль `deskagent.perception.accessibility` читает семантическое дерево интерфейса
через `AXUIElement`, ищет элементы по роли и тексту (включая fuzzy-поиск), возвращает
координаты, AX actions, confidence и повторно используемый `ax://` locator. Доступны
действия чтения, изменения состояния и отменяемые ожидания с таймаутом, например
`find_ui_element`, `press_ui_element`, `wait_for_ui_element` и
`verify_ui_element_state`.

Перед первым использованием вызовите `request_accessibility_permission`, затем
разрешите приложению доступ в **System Settings → Privacy & Security →
Accessibility**. Подробности контракта и внутренней архитектуры находятся в
[`deskagent/perception/accessibility/README.md`](deskagent/perception/accessibility/README.md).

## Наблюдение и составные actions

`capture_screen` и `capture_window` сохраняют PNG во временный файл с правами
`0600`. Для них нужно разрешение macOS **Screen & System Audio Recording**.
`read_screen_text` использует локальный Apple Vision OCR; зависимость
`pyobjc-framework-Vision` устанавливается из `requirements.txt`.

Дополнительно в `deskagent/actions/vision` есть 24 действия для изображений:
чтение размеров, цветовых свойств и метаданных; хеширование и сравнение файлов;
изменение размера, поворот, отражение, обрезка, добавление полей, конвертация,
настройка DPI и качества JPEG. Эти операции используют системный macOS `sips`.
OCR-действия находят текст и его координаты, читают заданную область,
показывают низкую уверенность распознавания, порядок строк, ближайший текст и
различия текста на двух PNG. Для них требуется локальный Apple Vision.
Изменённые изображения сохраняются в новые файлы в разрешённых каталогах.
Входной файл ограничен 50 МБ, а изображение — 100 млн пикселей.

`find_target`, `click_target` и `set_target_value` ищут цель через Accessibility,
DOM активной браузерной вкладки и, для поиска или клика по тексту, через OCR.
Параметр `backend` позволяет выбрать `accessibility`, `dom`, `ocr` или `auto`.
При неоднозначном результате action возвращает ошибку. Для сравнения состояния
до и после действия доступны `get_ui_snapshot`, `wait_for_ui_change` и
`verify_action_effect`.

Для системных диалогов добавлены `get_active_dialog`, `set_dialog_field`,
`choose_file_in_dialog`, `confirm_dialog`, `cancel_dialog` и
`read_permission_prompt`. Подтверждение требует точного имени кнопки и отдельного
одобрения пользователя. `choose_file_in_dialog` выбирает файл, но не нажимает
кнопку открытия.

Чтение PDF и текстовых документов предоставляют `read_pdf_pages`,
`search_in_document`, `extract_document_tables`, `get_document_summary` и
`compare_document_versions`. Сводка является извлечением фрагментов с номерами
страниц, а сравнение показывает различия строк. Для PDF нужны `pypdf` и
`pdfplumber` из `requirements.txt`.

В `deskagent/actions/documents` добавлены ещё 31 action:

- Анализ UTF-8 текста и Markdown: число строк и слов, диапазоны строк и
  абзацев, заголовки, частоты слов, повторяющиеся абзацы, ссылки, задачи и
  примерное время чтения.
- Инспекция PDF: метаданные, размеры страниц, закладки, текстовая статистика,
  ссылки, аннотации, поля формы, изображения и базовые признаки доступности.
- Создание новых PDF: объединение, извлечение и исключение страниц, смена
  порядка и поворот страниц, изменение метаданных, экспорт текста.
- Создание новых TXT/Markdown/reStructuredText: запись, замена и добавление
  текста, объединение файлов, извлечение строк, нормализация пробелов.

Новые операции ограничивают входной файл 25 МБ, текст 2 млн символов и PDF
500 страницами. Изменения сохраняются в новый файл в разрешённом каталоге;
исходники не перезаписываются. PDF actions используют `pypdf`, который должен
быть установлен из `requirements.txt`.

Диагностика доступна через `get_agent_capabilities` и
`check_action_availability`. Сохранённые задачи можно просмотреть actions
`get_task_progress`, `preview_task_effects`, `explain_last_action_failure`.

Для Apple Notes на macOS в `deskagent/actions/notes` добавлены 32 действия:
список аккаунтов, папок и заметок, поиск по названию и тексту, чтение заметки и
её HTML, вложения, выбранные и недавно изменённые заметки, статистика,
повторяющиеся названия, ссылки и проверка содержимого. Можно создать заметку
или папку, добавить текст, переименовать, переместить, дублировать и показать
заметку в приложении, а также экспортировать текст или HTML в новый файл.
Изменения адресуются по ID и перечитываются для проверки результата. Изменение
заблокированных, общих заметок и заметок с вложениями запрещено; экспорт не
перезаписывает файлы. При первом использовании macOS может запросить разрешение
на управление Notes через Automation.

В `deskagent/actions/music` доступны 47 действий для Apple Music на macOS:
состояние плеера, воспроизведение, переход по трекам, позиция, громкость,
отключение звука, перемешивание и повтор. Библиотеку можно искать по названию,
исполнителю, альбому и жанру; доступны избранные и непрослушанные треки,
группировка по исполнителям, альбомам и жанрам, тексты песен и статистика.
Плейлисты можно просматривать, искать внутри них, создавать, переименовывать и
пополнять треками. Доступны рейтинг, избранное, комментарий, жанр и темп
трека. Действия используют постоянные ID Music, ограничивают размер выдачи и
перечитывают состояние после изменения. При первом вызове macOS может
запросить разрешение Automation для Music. Поиск просматривает не более 5000
треков за вызов и отмечает неполный результат.

Платформенные адаптеры для новых функций находятся в `deskagent/platform`:
контракты `base/audio.py`, `base/image.py`, `base/music.py`, `base/notes.py`,
`base/vision.py`
и реализации `macos/audio.py`, `macos/music.py`, `macos/notes.py`,
`macos/vision.py`, `macos/image.py`. `ServicesFactory` подключает их через
`context.services`. Кодовые, документные и productivity actions работают
с файлами и хранилищем через общие Python-библиотеки; отдельного macOS backend
для этих операций не требуется. Диагностика доступности отмечает действия,
которым нужна macOS.

В `deskagent/actions/productivity` добавлены ещё 40 actions для наблюдения за
автопилотом. Они читают список задач, отдельные шаги и их результаты, события,
блокировки, повторы, зависимости, попытки, проверки, подтверждения, вызовы
actions, артефакты и метрики. Для workflow доступны версии, входные параметры,
расписание, история запусков и предпросмотр плана без его запуска. Переданный
план можно проверить, упорядочить по зависимостям, оценить критический путь,
риски, повторы, параллельные группы и шаги с подтверждением. Эти действия не
запускают задачи и не меняют их сохранённое состояние; результаты ограничены
по размеру, чувствительные поля скрываются.

Для кодовых проектов доступны `get_git_status`, `show_git_diff`,
`run_project_tests` и `read_test_failures`. Git diff пропускает известные
чувствительные пути. Запуск pytest разрешён только в каталогах из
`security.allowed_paths` и требует подтверждения; отчёты сохраняются в закрытой
папке рядом с базой автопилота.

В `deskagent/actions/code` добавлены ещё 34 read-only actions. Они показывают
ветки, теги, коммиты, историю файлов, blame, изменённые и конфликтующие файлы,
статистику diff и связь с upstream. Для исходников доступны дерево проекта,
поиск текста и символов, список импортов, TODO-маркеры, манифесты зависимостей,
дубли файлов, крупные файлы, инвентарь тестов и проверка синтаксиса Python через
AST без запуска кода. Обход ограничен 5000 файлами и 2 МБ на исходный файл;
чувствительные пути исключаются из результатов. Запуск тестов остаётся
отдельным действием с подтверждением.

Дополнительные браузерные действия наблюдают состояние страницы без возврата
всего текста в контекст модели: `get_page_snapshot`, `wait_for_page_change`,
`verify_page_text`, `get_page_outline`, `find_page_element_by_role`,
`count_dom_elements`, `verify_dom_element_state`, `wait_for_dom_element_state`.

Локальные аудио-действия macOS используют системные `say`, `afplay` и `afinfo`:
`list_system_voices`, `speak_text`, `render_speech_to_file`, `play_audio_file`,
`get_audio_file_info`. Создание AIFF ограничено разрешёнными путями и не
перезаписывает существующий файл. Воспроизведение и синтез можно отменить через
механизм отмены action executor.

В `deskagent/actions/audio` также доступны 31 action для обработки аудио:

- Анализ WAV: параметры файла, уровни по каналам, тишина и активность, форма
  сигнала, клиппинг, баланс стерео, частота пересечения нуля и сравнение файлов.
- Монтаж WAV: обрезка, склейка, микширование, усиление, нормализация, плавные
  переходы, реверс, работа с каналами, вставка тишины, деление на части и
  удаление тишины по краям.
- Генерация WAV: тон, частотный свип, белый шум, тишина и метроном.
- Конвертация через macOS `afconvert`: WAV/AIFF/CAF с PCM 16 бит, изменение
  частоты дискретизации и числа каналов, извлечение аудиодорожки.

Анализ, монтаж и генерация работают с несжатым WAV PCM 16 бит (1–8 каналов,
8–192 кГц); отдельные операции ограничены моно и стерео. Лимит обработки —
20 млн отсчётов. Все операции записи создают новые файлы только в разрешённых
каталогах и не перезаписывают существующие.
